# 마왕성 인사팀 · 출근부 (tools/desk)

1인 개발용 출퇴근 + 할 일 + 데브로그 데스크. 브라우저에서 돌아가는 로컬 앱이고, 기록은 전부 `production/desk/` 아래 md 파일로 남는다.

- 의존성 0 — Node만 있으면 된다 (npm install 없음).
- 앱은 입력창일 뿐, **원본은 md 파일**. 앱을 갈아엎어도 기록은 남는다.
- 루프: **출근**(오늘 할 일 고르기) → 작업(줄마다 완료·진행 중·예정) → **퇴근**(제목 필수 + 메모·다음에 할 것) → 데브로그 md 완성("한 일"은 자동) → 데이터 폴더(+ 마일스톤 판)만 커밋·푸시.
- 위쪽 **「마일스톤 판」** 버튼 = 데모까지 마일스톤 7개 × 아트·기획·코드 일정판 (2026-10-02, 아래 "마일스톤 판").

## 실행

| 환경 | 켜기 | 끄기 |
|---|---|---|
| Windows | `tools/desk/출근.bat` 더블클릭 (바탕화면 바로가기 추천) | `tools/desk/출근부-끄기.bat` |
| Mac | `tools/desk/출근.command` 더블클릭 (실행 권한은 커밋에 포함) | `tools/desk/출근부-끄기.command` |
| 직접 | 리포 루트에서 `node tools/desk/server.js` (창에 로그가 보임) | Ctrl+C |

실행 파일은 먼저 `git pull --ff-only`로 다른 기계의 기록을 받아온 뒤, 서버를 **창 없이 백그라운드로** 켜고 브라우저(`http://localhost:4123`)를 연다. 실행 파일 창은 2초 뒤 저절로 닫히고, 서버 출력은 `tools/desk/desk.log`(git 무시)에 쌓인다. 이미 켜져 있으면 브라우저만 다시 연다. 서버는 안 꺼도 된다(PC를 끄면 같이 꺼짐). 실수로 꺼져도 기록은 파일에 있으니 다시 더블클릭하면 된다.

옵션: `--no-open`(브라우저 안 열기) · `--no-git`(퇴근 시 커밋/푸시 생략) · 환경변수 `DESK_DATA_DIR`(데이터 폴더), `DESK_PORT`(포트) — 둘 다 테스트용.

## 부재 · 뽀모도로

- **부재 / 복귀**: 점심이나 휴식처럼 자리를 비울 때 `부재`, 돌아오면 `복귀`. 현재 세션이 닫히고 복귀 때 새 세션이 열리므로(`sessions`에 줄이 나뉨) 그 사이 시간은 근무에서 자동으로 빠진다. 부재 중에도 퇴근할 수 있다. 복귀를 잊었으면 파일의 `sessions`를 손으로 고치면 된다.
- **뽀모도로**: 근무 중 카드에서 `집중 시작`을 누르면 50분 카운트다운. **시계와 알림은 서버가 맡는다** — 끝나면 서버가 윈도우 알림 + 소리(맥은 맥 알림)를 직접 띄우므로 **크롬을 꺼도 알림이 온다.** 이어서 10분 휴식이 자동으로 시작되고, 휴식이 끝나면 다시 알림이 오며, 다음 집중은 버튼으로 시작한다. 휴식 시간은 근무 시간에서 빼지 않는다(짧고 리듬의 일부). 완료한 집중 블록 수는 그날 파일의 `pomodoros`에 쌓인다. 부재나 퇴근을 누르면 돌아가던 뽀모도로는 멈춘다. **집중을 중간에 멈추면**(중지 버튼·부재·퇴근) 개수는 오르지 않고, 그때까지의 분이 그날 파일의 `partialMinutes`에 더해진다(1분 미만은 버린다). **뽀모도로는 쓰고 싶을 때만 쓰는 타이머라, 개수와 집중 시간은 화면 어디에도 보여 주지 않는다** (2026-10-07, 사용자 — 옛 "뽀모도로 2개 + 40분" 표시, 주·월 막대의 안쪽 집중 막대, 집중 비율을 뺐다). 파일에는 계속 적히고, 서버 `stats.js`는 `focusHours`를 계산만 해 둔다. 화면이 열려 있으면 2초마다 서버 상태를 받아 카운트다운을 보여준다. 서버가 재시작돼도 `tools/desk/.pomo.json`(git 무시)으로 이어간다. 시간은 `desk.config.json`의 `pomodoro`로 바꾼다.
- **스트림덱 버튼**: `tools/desk/pomo-start.vbs`를 Open 액션에 걸면 브라우저 없이 집중을 시작한다. 이미 집중 중이면 시계를 되돌리지 않고 남은 시간만 알려 준다. 한글 알림 때문에 이 파일만 UTF-16으로 저장한다(`.gitattributes`에 적혀 있다).
- **알림 확인**: 패널의 `알림 테스트` 버튼을 누르면 바로 윈도우 알림이 떠야 한다. 안 뜨면 윈도우 설정 → 시스템 → 알림에서 "Windows PowerShell" 앱 알림이 켜져 있는지 확인(알림을 PowerShell 을 통해 띄운다). 방해 금지 모드면 알림 카드는 숨겨지지만 소리는 난다. 크롬 쪽 설정은 필요 없다.

## 마일스톤 판 (2026-10-02)

출근부 위쪽 `마일스톤 판` 버튼(같은 탭) → `board.html`. 마일스톤 7개를 가로로, 아트·기획·코드를 가로 띠로 놓은 일정판이다. 원래 claude.ai 아티팩트였는데, 10/4에 Claude 계정을 바꾸면 못 열 수 있어서 출근부로 옮겼다(색·글꼴·배치는 아티팩트 그대로 — 구글 글꼴을 쓰므로 인터넷이 끊기면 맑은 고딕으로 보인다).

- **끌어서 옮기기**: 카드를 다른 칸이나 순서로 끌어다 놓는다. 끌기가 안 되면 카드를 누르고 옮길 칸의 `여기로`.
- **날 수 고치기**: 카드 오른쪽 숫자를 누르면 입력칸(0.5 단위). 손으로 고치면 Claude 어림 표시(점선 테두리)가 떨어진다.
- **합계 막대**: 칸마다 "들어간 날 / 마일스톤 날 수". 85% 넘으면 노랑, 100% 넘으면 빨강 + "넘침".
- 옮기거나 고친 카드는 노란 테두리 → `저장`을 눌러야 파일에 적힌다. `저장 안 한 변경 버리기` = 서버에서 판을 다시 받는다. 저장 안 한 채 판을 떠나면 브라우저가 한 번 묻는다.
- `글로 복사` = 판을 글로 바꿔 클립보드에 (Claude 대화창에 붙여 넣는 용도).
- **데이터 = `production/milestones/board.json`** (`desk.config.json`의 `boardFile`). 마일스톤 하나·카드 하나가 한 줄이라 git에서 바뀐 카드만 보이고, 손이나 Claude가 고치기 쉽다. 카드 칸 = `id`·`m`(마일스톤)·`l`(갈래 a 아트 / p 기획 / c 코드)·`t`(이름)·`d`(날 수)·`est`(Claude 어림)·`from`(당겨 온 곳)·`n`(회색 설명). 판 화면은 카드를 옮기고 날 수만 고친다 — 카드·마일스톤을 더하거나 빼는 일은 파일에서 한다.
- **다른 곳에서 고친 판은 덮어쓰지 않는다**: 판을 받을 때 파일의 지문을 같이 받고, 저장할 때 그 지문이 지금 파일과 다르면(그사이 Claude가 파일을 고쳤거나 맥북 기록을 pull했으면) 서버가 거절한다. 그때는 `글로 복사`로 남겨 둔 뒤 `저장 안 한 변경 버리기`로 새 판을 받는다.
- 서버 주소: `GET /api/board` (판 + 지문) · `POST /api/board` `{ version, cards }` (지문이 다르면 409). 파일 읽기·쓰기·검사 = `board.js`, 화면 = `public/board.html`·`board.css`·`board-app.js`.
- 퇴근할 때 데이터 폴더와 같이 커밋·푸시된다(아래 "git 동작").
- 아직 없는 것: M01에서 끝낸 항목 표시, 카드 더하기·빼기.

## 맥북과 같이 쓰기

리포가 GitHub에 있으니 별도 서비스 없이 git으로 맞춘다.

1. 맥에 Node 설치 + 리포 클론.
2. 출근 = 실행 파일이 `git pull` → 최신 기록 반영.
3. 퇴근 = 앱이 `production/desk/`만 골라 커밋하고 `git push`.
4. 데브로그가 하루 한 파일이라 두 기계가 같은 파일을 건드릴 일이 거의 없다.

푸시가 실패해도(오프라인 등) 기록은 로컬 md에 남아 있다. 다음에 온라인에서 `git push`만 하면 된다. 맥에서 첫 푸시는 터미널에서 한 번 직접 해서 GitHub 인증을 끝내 두는 게 편하다.

## 데이터 (`production/desk/`)

```text
production/desk/
├── todo.md                 # 할 일 — 상태 5개 체크박스 + 다음 줄 메모 (아래 참고)
└── devlog/
    └── 2026-09-09.md       # 하루 한 파일. 출근 시 생성, 퇴근 시 완성
```

### todo.md 형식 (2026-09-13 ver02)

```markdown
## 할 일
- [ ] [M00-02] 출근부: 마일스톤 파일 읽기      ← 열림. `[M00-02]` 는 마일스톤 항목 id (있으면 id 로 같은 항목인지 판단)
- [/] 고블린 텍스처
  > 진행: 모델링 끝, 텍스처 남음 · 2026-09-13   ← 진행 중 + 메모 줄 (들여쓰기 2칸, `> 진행|보류|완료|취소|메모:`)
- [>] 스트림덱 설정
  > 보류: 장비 도착 후 · 2026-09-13
- [?] 뭔가                                     ← 앱이 모르는 상태. 화면에 `[?]` 로만 보이고 절대 고치지 않는다

## 완료
- [x] 출근부 첫 퇴근 해보기
  > 완료: 2026-09-13
- [-] 테스트 UI
  > 취소: 필요 없음 · 2026-09-11
```

- **앱이 이해하지 못한 줄은 절대 지우지 않는다.** 파서(`tools/desk/todo.js`)는 파일을 "할 일 블록"과 "그 밖의 줄"로 나눠 읽고, 저장할 때 **바뀐 할 일 블록만** 다시 만들고 나머지(제목·빈 줄·주석·모르는 상태·할 일 아래 들여쓴 줄)는 원문 그대로 둔다. 손 안 댄 파일은 글자 하나 안 바뀐다.
- 완료·취소로 바꾸면 `## 완료` 맨 위로, 되돌리면 `## 할 일` 맨 위로 옮긴다. 열림↔진행↔보류는 제자리. 화면의 "할 일" 목록은 진행 중 → 열림 → 모름 → 보류 순.
- ver01 형식 `- [x] 항목 (2026-09-09)` 도 읽는다(꼬리표 = 완료 날짜). 그 항목을 건드릴 때만 새 형식으로 바뀐다.
- 저장은 임시 파일에 쓴 뒤 이름을 바꿔 끼우는 방식(atomic) — 저장 중 꺼져도 반쪽 파일이 안 남는다. 읽을 때는 BOM 을 뗀다. 데브로그도 같다.
- 테스트: `node --test tools/desk/test/todo.test.js tools/desk/test/stats.test.js tools/desk/test/board.test.js` (Node 내장 `node:test`, 의존성 0 — todo 파서·주월 집계·마일스톤 판, 모두 27개).

### 이어가기 (2026-09-13 ver02, M00-01)

- 퇴근 보고의 "다음에 할 것" 각 줄은 `todo.md` "할 일" 절 끝에 새 항목으로 들어간다. 같은 문장이거나 같은 `[M00-NN]` id 가 이미 있으면(완료 포함) 건너뛴다. 퇴근 토스트에 "N개 추가"가 보인다.
- **출근 전 화면 = 왼쪽 "오늘 할 일" 칸 + 오른쪽 대기 목록. 위치가 곧 상태.** 카드를 오른쪽에서 왼쪽으로 끌면(또는 `추가`) 오늘 할 일, 왼쪽에서 오른쪽으로 끌면(또는 `−`) 대기. 왼쪽 안에서 위아래로 끌어 순서를 정하면 출근 도장을 찍을 때 그 순서가 데브로그 `picked` 순서로 기록된다. 고르기용 체크박스는 없고, 출근 전 오른쪽에는 완료 체크도 없다(실수 방지 — 완료는 출근 뒤 왼쪽 목록에서).
- 오른쪽 대기 목록 순서는 서버 규칙: 진행 중 → 어제(가장 최근 퇴근한 날)의 "다음에 할 것"(적은 순서, `어제 이어가기` 표식) → 열림 → 모르는 상태. 보류는 "보류 N개"로 접혀 있고 펼치면 `해제`로 열림으로 되돌린다.
- **추천은 노란색** (2026-10-01): 그 순서의 맨 앞 `maxPick`개(기본 3개)가 추천이다. 대기 목록 맨 위에 "추천"이라는 이름표 아래 노란 줄·노란 글씨로 묶여 보이고, 그 아래 "그 밖의 할 일"에 나머지가 목록 순서대로 나온다. 추천은 안내일 뿐이라 아무 항목이나 골라도 된다. `todo.md`의 "할 일" 순서가 곧 추천 순서다(진행 중과 어제 이어가기가 먼저).
- 미리 올려 두는 카드는 **1장만**: 어제의 다음 첫 줄 → 없으면 메모 날짜가 가장 최근인 진행 중 → 없으면 없음. 관성으로 어제 일을 전부 다시 고르는 걸 막기 위해서다. 원치 않으면 다시 끌어 내리면 된다.
- **출근 뒤 왼쪽 "오늘 할 일" 줄마다 [완료 | 진행 중 | 예정]** (체크박스 대체). 누르면 즉시 todo.md 에 저장된다 — 완료는 `[x]` + 데브로그 done, 진행 중은 `[/]` + "어디까지" 한 줄(선택, Enter 로 저장), 예정은 열림 그대로(진행 메모가 있었으면 메모 줄로 보존). 기본값은 현재 상태라 완료만 직접 누르면 된다. 퇴근 보고 폼 위에 같은 줄이 다시 나와 확인만 하면 된다.
- 출근 뒤 왼쪽 목록의 드래그·순서 바꾸기와 오른쪽 ⋯ 메뉴(보류·취소)는 아직 없다 (M00-09).
- 규칙은 서버(`todo.js`의 `pickList`)가 계산하고 화면은 `state.pick`을 보여만 준다 — today.md·주간 회고가 같은 규칙을 쓴다.

- **"한 일"은 앱이 쓴다** (2026-09-15): 오늘 고른 항목의 상태로 `[완료] 본문` / `[진행] 본문 — 어디까지`. 진행 중·예정 항목은 "다음에 할 것"에 자동으로 들어가 다음 출근의 "어제 이어가기"가 된다. 사람이 적는 건 제목(필수)·메모·다음에 할 것(새로 떠오른 것만)이다. ver01 파일의 "배운 것/막힌 것" 절은 그대로 보존된다.
- **"하루 요약" 칸** (2026-10-01): 퇴근 뒤 Claude 가 그날 무엇을 했고 무엇을 정했는지 요약해, 사용자 확인을 받고 데브로그 파일 맨 아래 `## 하루 요약`에 줄마다 `- `로 적는다. 퇴근 폼에는 없는 칸이다 — 앱은 이 칸을 보존만 하고, "지난 데브로그"의 날짜 카드에서 "메모" 아래에 읽어서 보여 준다(순서 = 한 일 → 메모 → 하루 요약 → 다음에 할 것. 글자색은 칸 제목과 본문 사이의 밝기). 글자 그대로 보여 주므로 굵은 표시(`**`)는 쓰지 않는다.
- **퇴근 뒤 카드 = 오늘 결과표**: 완료(✓)·진행 중(◐, 메모)·예정(→) 한눈에. 같은 날 "다시 출근"은 오늘 고른 항목을 그대로 이어간다.
- **주 · 월 보기** (2026-09-15): "지난 데브로그" 카드의 [일 | 주 | 월] 전환. 주 줄 = `W38 · 9/14 ~ 9/20 · 출근 4일 · 22.1h · 완료 3`. 펼치면 요일별 근무 시간 막대와 날짜 줄(2026-10-07에 집중 시간·비율과 안쪽 집중 막대를 뺐다 — 위 "뽀모도로"), 완료한 것·주말에 진행 중으로 남은 것·결정(`결정:` 메모) 목록. 월은 주별 막대 + 주 줄. 막대에 마우스를 올리면 툴팁. 숫자는 서버 `stats.js`가 데브로그만으로 계산(`state.periods`) — 금요일 회고 통계·today.md 도 같은 함수를 쓴다.- **지난 데브로그**: 줄을 누르거나 히트맵 칸을 누르면 그 자리에서 같은 모양의 카드로 펼쳐진다(모달 없음). 그날 파일의 "한 일"(`[완료]`/`[진행]`)·메모·다음에 할 것만 보이고 빈 절은 안 보인다. 옛 파일의 빈 "배운 것/막힌 것" 절은 그날을 다시 저장할 때 지워진다(내용이 있으면 보존).

- 머리(frontmatter) 항목 이름은 영어(title/date/hours…)로 두었다 — 나중에 공개 데브로그 사이트를 만들 때 정적 사이트 생성기(Astro, Hugo 등)가 그대로 읽는다.
- 손으로 고쳐도 된다. 앱은 다음 요청 때 다시 읽는다.
- `status`는 `open`(근무 중) / `away`(부재 중) / `closed`(퇴근 완료). `hours`는 닫힌 세션의 합이라 부재 시간이 빠져 있다.
- 하루에 두 번 출근하면 `sessions`에 줄이 하나 더 붙고, 퇴근 보고는 이전 내용이 채워진 채로 다시 열린다. 부재·복귀도 같은 방식으로 줄이 나뉜다.
- 자정을 넘겨 퇴근하면 출근한 날짜의 파일에 기록된다.

## git 동작

퇴근 시 앱이 실행하는 것: `git add -A -- production/desk production/milestones/board.json` → `git commit -m "desk: 날짜 퇴근 (시간) — 요약" -- (같은 두 곳)` → `git push`. 이 두 곳 바깥의 변경(작업 중인 다른 파일)은 건드리지 않는다. 마일스톤 판은 2026-10-02부터 같이 올린다 — 맥북에서도 같은 판이 보이게.

## 문제가 생기면

- **포트가 이미 사용 중**: 이미 켜져 있는 것. 브라우저만 열린다. 다른 프로그램이 4123을 쓰면 `port`를 바꾼다.
- **퇴근했는데 푸시 실패 토스트**: 기록은 저장됐다. 터미널에서 `git push` 한 번.
- **화면이 비어 있음**: 서버 창이 켜져 있는지 확인. `node tools/desk/server.js`를 직접 실행하면 오류가 보인다.
