> 이전 전투 로드맵은 git 히스토리에 보존. 기획 기준 = [mvp-design.md](mvp-design.md).
> 📦 **2026-09-12**: Origin 트랙 해체 → 이 파일만 `design/concept/build-roadmap.md`로 이동. 순서는 **GDD v1 확정 → game/ 착수**(병행 안 함). GDD v1 뒤 이 순서를 바탕으로 마일스톤을 다시 짠다 — 검증 포인트 3개는 그대로 승계. 작업 방식 원칙("이해하며 만들기")은 루트 CLAUDE.md "일하는 법"에.
> 🧭 **2026-09-30 마일스톤을 새로 짬**: 순서가 **기획과 제작을 번갈아 한다**(곧 만들 부분의 GDD만 쓰고 바로 그 부분을 만든다)로 바뀌었다. 위의 "GDD v1 확정 → game/ 착수"를 대신한다. 이 파일의 0~9단계는 [production/milestones/](../../production/milestones/README.md) M01~M07에 합쳐졌다 — 맨 아래 "어느 단계가 어느 마일스톤이 됐나" 참고. 확인하기로 한 세 가지와 진행 원칙은 그대로다.

목표: **"간파가 재밌고, 도장이 손맛 있는" 면접 데스크 MVP**를, 유니티를 처음부터 이해하며 만든다.
각 단계마다 눈에 보이는 결과물이 하나씩 나오도록 순서를 짰다.

> 표기: 단계별 상세 워크북은 game/ 착수 때 위치를 정해 따로 작성한다.
> 이 파일은 "지도"만.

## 진행 원칙

- 한 번에 한 걸음. 개념을 이해하고 넘어간다. **이해 기준 = 디렉터 수준** (뭘 하는지·왜 이 방식인지 설명 가능하면 통과. 밑바닥까지 파지 않는다).
- 이 컨셉은 배틀테스트를 거치지 않은 신규 방향 — **검증 포인트가 3개**다:
  - **1단계 끝 → "분위기가 사는가?"** (촛불 사무실, 코지+사악)
  - **2단계 끝 → "도장이 계속 찍고 싶은가?"** ← 물성 심장. 안 살면 멈추고 재설계
  - **5단계 끝 → "간파했을 때 '오?'가 있는가?"** ← 후크 심장
- 전투 MVP 대비 기술 난이도↓ (대량 렌더링·리깅·결정론 시뮬 불필요) — **완주 가능성이 높은 트랙**. 대신 콘텐츠(대사·지원자) 작성이 뒤로 갈수록 비중↑.

## 단계

### 0단계 · 유니티랑 친해지기 (변화 없음)
새 프로젝트(**Unity 6000.5.1f1** + URP) 생성 — 위치 = 저장소 최상위 `game/` (Unity Hub: Location `C:\DungeonHR`, Project name `game`), 화면 둘러보기, 저장.
- 배울 개념: Scene(무대), GameObject, Inspector, Play 모드, Scene 뷰 이동/회전.
- 생성 직후 `game/CLAUDE.md` 한 장 추가: 루트 CLAUDE.md "일하는 법"의 이해하며 만들기 원칙 + 이 로드맵 링크 (하위 폴더 CLAUDE.md는 그 폴더를 만질 때만 읽히므로 필요).

### 1단계 · 보이는 공간 — 마왕성 사무실
책상 클로즈업 고정 카메라 → 촛불 조명(따뜻+어두운 대비) → 임시 소품(책상·의자·석벽) → 후처리(Bloom/DOF/비네트).
- 배울 개념: Transform, Camera(고정 데스크 뷰), Light(포인트 라이트 + 촛불 플리커), Material, URP Post-processing.
- 목표 레퍼런스: [refs/면접화면-목업.png](refs/면접화면-목업.png) — 코지+사악 대비.
- 소품은 임시 프리미티브로 충분 (로우폴리 3D 교체는 4단계). **조명·후처리가 이 단계의 심장.**
- 기존 `refs/` 읽기자료(미니어처 룩·조명)는 실내 디오라마에도 유효 — 잔디/바람 부분만 백로그로.
- ✅ **점검 1: 분위기가 사는가?**

### 2단계 · 책상 위 물건 — 도장의 손맛
마우스로 물건 집기/드래그/놓기 → 도장 드래그 → **쾅** (잉크 자국 + 소리 + 화면 흔들림).
- 배울 개념: Input(마우스 레이캐스트), 스크립트 기초(MonoBehaviour), AudioSource, 간단 트윈(DOTween).
- ✅ **점검 2: 도장이 계속 찍고 싶은가? (물성 심장 — 안 살면 여기서 멈추고 재설계)**

### 3단계 · 서류 심사 루프 (게임 뼈대)
이력서 데이터 → 화면 표시 → JD 공문과 대조 → 도장 판정 → 정답 채점 → 다음 서류.
- 배울 개념: ScriptableObject/JSON 데이터 외부화, 게임 상태 흐름(면접 시작→판정→다음), UI 기초.
- = MVP의 M0 그레이박스. 판정 데이터 구조(JD·자질·정답 룰·일일 지침)를 여기서 검증.

### 4단계 · 첫 몬스터 등장
블렌더 복셀풍 로우폴리로 고블린 1체 (2026-08-18 변경 — MagicaVoxel 폐기, [데스크 가이드](../../docs/pipeline/blender-lowpoly-desk-guide.md) 방식을 캐릭터로 확장) → 임포트 → 책상 너머 배치 → **리액션 2종(긴장/안도)** + 땀 이펙트. 책상 소품은 로우폴리 3D로 교체.
- 배울 것: 블렌더 박스 모델링(캐릭터 편), 모델 임포트, 간단 애니메이션(Animator 기초).
- ⚠️ 전투 트랙과 달리 **Blender 풀 리깅 불필요** — 리액션 2종은 스케일/포지션 트윈 + 표정 스왑 수준으로 시작.

### 5단계 · 면접 루프
질문 카드 선택(포인트 제한) → 답변 텍스트 + 반응 연출 → 판단.
- 배울 개념: 대사 데이터 파이프라인, 카드 UI, 연출 시퀀싱.
- ✅ **점검 3: 간파했을 때 "오?"가 있는가? (후크 심장)**

### 6단계 · 하루 구조
출근 → 서랍에서 공문 확인 → 심사/면접 N건 → 퇴근 결산(신문 1면 + 동료 대사) → 지연 사고 보고서.
- 배울 개념: 씬/상태 전환, 세이브 없는 세션 흐름, 결산 데이터 집계.

### 7단계 · 승진 & 가젯
성과 판정 → 승진 연출 → 가젯 지급(촛불 위조 검사·돋보기 거짓 판독) + 카드 해금.
- 배울 개념: 진행 상태 관리, 가젯 인터랙션(대상에 갖다 대기), 언락 시스템.

### 8단계 · 콘텐츠 & 3일 빌드
지원자 14~18건 작성, Day 1~3 지침 변주(사기 부서의 날 = 클라이맥스), 용사 스파이.
- 배울 것: 콘텐츠 파이프라인 굳히기, 난이도 배치(명백/간파/함정 분포).

### 9단계 · 폴리시 & 플레이테스트
사운드·연출 다듬기 → 15~20분 데모 완성 → 검증 기준([mvp-design.md §12](mvp-design.md)) 통과 확인 → 공모전 컷(2027-04).
