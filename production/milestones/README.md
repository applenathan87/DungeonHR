## 하루에 세 가지 작업을 섞는다

하루를 한 가지 일로 채우지 않는다. 아래 세 가지를 매일 섞고, 출근부의 오늘 할 일에 종류마다 하나씩 올린다.

- **아트 작업** — 강의 듣기 → 면접실 만들기 → 텍스처 칠하기 → 몬스터 늘리기와 품질 올리기
- **기획 작업** — GDD 쓰기와 케이스 쓰기(케이스는 M03부터, 그때 만드는 기능에 쓸 것을 같이 쓴다) → 문구 다듬기
- **코드 작업** — M01·M02에는 없다 (유니티는 면접실을 올려 보는 데만 쓴다). M03부터 시작

하루 시간을 어떻게 나눌지는 마일스톤 파일마다 적고, 해 보면서 고친다. M01 = 강의 2 · 실습 1 · GDD 2 (뽀모도로 개수).

## 일하는 규칙

- **한 번에 한 마일스톤만 진행한다.** 진행 중인 마일스톤 파일에만 할 일 목록이 있다.
- **할 일은 전부 [todo.md](../desk/todo.md)에 올려 둔다**: 진행 중인 마일스톤의 할 일을 짧은 이름 한 줄로, 번호 없이, 권하는 순서대로 올린다 (2026-10-01). 아침에 출근부에서 작업 종류마다 하나씩, 최대 3개를 고른다. 순서는 추천일 뿐이고 어느 것을 골라도 된다. 자세한 내용은 마일스톤 파일에서 같은 이름으로 찾는다.
- **크기**: 항목 뒤의 (하루)는 하루치, (이틀)은 이틀치다. 그보다 크면 쪼갠다. 다음 날로 두 번 넘어간 항목도 쪼갠다.
- **GDD**: 하나를 시작할 때마다 새 세션에서 `/design-system`. 검토도 새 세션에서 `/design-review [파일] --depth lean`. 질문은 글로 주고받는다. 끝나면 [systems-index.md](../../design/gdd/systems-index.md)의 상태 칸을 고친다.
- **케이스는 기능과 같이 쓴다**: 그 마일스톤에서 만드는 기능에 쓸 실제 케이스를 같은 마일스톤에서 쓴다 — M03 Day 1 서류, M04 Day 2 면접, M05 Day 3. 끝날 때 답할 질문에는 대충 쓴 임시 케이스가 아니라 실제 케이스로 답한다. 그래서 M03·M04의 하루 시간 나누기는 코드 2 · 기획 2 · 아트 1이다.
- **마일스톤을 끝낼 때**: 질문에 한 줄로 답한다(통과 / 고쳐서 계속 / 다시 설계) → 다음 마일스톤의 할 일 목록을 채우고 todo.md에 올린다 → 파일 맨 위 `status`를 바꾼다 → 루트 CLAUDE.md "지금" 줄을 고친다.
- 소품·케이스·에셋의 자세한 목록은 각 주제의 문서에 두고, 여기에는 하루 이틀 크기의 항목만 둔다.
