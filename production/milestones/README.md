## 하루에 세 가지 작업을 섞는다

하루를 한 가지 일로 채우지 않는다. 아래 세 가지를 매일 섞고, 출근부의 오늘 할 일에 종류마다 하나씩 올린다.

- **아트 작업** — 스컬핑 연습 → 면접실 만들기 → 텍스처 칠하기 → 몬스터 늘리기와 품질 올리기. 강의는 할 일에 넣지 않고 그때그때 골라 듣는다 — 들은 날 출근부에 "블렌더 강의"처럼 직접 적고 배운 것을 메모한다(2026-10-03). 마일스톤 판에는 시간 몫으로 「아트 공부」 카드를 둔다
- **기획 작업** — GDD 쓰기와 케이스 쓰기(케이스는 M02 끝부터, 그때 만드는 기능에 쓸 것을 같이 쓴다) → 문구 다듬기
- **코드 작업** — M01·M02에는 없다 (유니티는 면접실을 올려 보는 데만 쓴다). M03부터 시작

하루 시간을 어떻게 나눌지는 마일스톤 파일마다 적고, 해 보면서 고친다. M01 = 아트 3(아트 공부 포함) · 기획 2 (뽀모도로 개수).

## 일하는 규칙

- **한 번에 한 마일스톤만 진행한다.** 진행 중인 마일스톤 파일에만 할 일 목록이 있다.
- **할 일은 전부 [todo.md](../desk/todo.md)에 올려 둔다**: 진행 중인 마일스톤의 할 일을 짧은 이름 한 줄로, 번호 없이, 권하는 순서대로 올린다 (2026-10-01). 아침에 출근부에서 작업 종류마다 하나씩, 최대 3개를 고른다. 순서는 추천일 뿐이고 어느 것을 골라도 된다. 자세한 내용은 마일스톤 파일에서 같은 이름으로 찾는다.
- **크기**: 항목 뒤의 (하루)는 하루치, (이틀)은 이틀치다. 그보다 크면 쪼갠다. 다음 날로 두 번 넘어간 항목도 쪼갠다.
- **GDD**: 하나를 시작할 때마다 새 세션에서 `/design-system`. **규칙 쪽(개요·플레이어가 느낄 것·상세 규칙·다른 시스템과의 관계)을 먼저 쓰고, 숫자 쪽(공식·예외 상황·조절값·통과 기준)과 검토는 그 부분의 코드 직전에 채운다** (2026-10-02 — 쓰는 순서 = [game-flow.md](../../design/gdd/game-flow.md) 7번). 검토는 새 세션에서 `/design-review [파일] --depth lean`. 질문은 글로 주고받는다. 끝나면 [systems-index.md](../../design/gdd/systems-index.md)의 상태 칸을 고친다.
- **케이스는 기능과 같이 쓴다**: 그 마일스톤에서 만드는 기능에 쓸 실제 케이스를 같은 마일스톤에서 쓴다 — M02 끝-M03 사원 단계 서류, M04 대리 Lv1(+Lv2 시작), M05 대리 Lv2·Lv3. 레벨마다 최소 이틀치, 합 36-48건(game-flow 5번). 끝날 때 답할 질문에는 대충 쓴 임시 케이스가 아니라 실제 케이스로 답한다. 그래서 M03·M04의 하루 시간 나누기는 코드 2 · 기획 2 · 아트 1이다.
- **마일스톤 판**: 마일스톤 7개 × 아트·기획·코드의 카드와 날 수 어림을 한 화면에서 본다 — 출근부 위쪽 「마일스톤 판」 버튼, 데이터 = [board.json](board.json), 쓰는 법 = [tools/desk/README.md](../../tools/desk/README.md). 다음 마일스톤의 할 일 목록은 판의 카드에서 채운다.
- **마일스톤을 끝낼 때**: 질문에 한 줄로 답한다(통과 / 고쳐서 계속 / 다시 설계) → 다음 마일스톤의 할 일 목록을 채우고 todo.md에 올린다 → 파일 맨 위 `status`를 바꾼다 → 루트 CLAUDE.md "지금" 줄을 고친다.
- 소품·케이스·에셋의 자세한 목록은 각 주제의 문서에 두고, 여기에는 하루 이틀 크기의 항목만 둔다.
