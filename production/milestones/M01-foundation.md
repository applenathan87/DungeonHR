## 할 일 목록

적는 법 = `종류: 이름 (크기) — 내용과 끝났다고 보는 조건`. 번호는 붙이지 않는다.

**같은 이름이 [todo.md](../desk/todo.md)에 한 줄씩 전부 올라가 있다.** 출근부에서 하고 싶은 것을 고르고, 자세한 내용은 여기서 같은 이름으로 찾는다. todo.md의 순서는 권하는 순서일 뿐이다 — 어느 것을 먼저 해도 된다.

GDD는 여덟 칸으로 쓴다: 개요 · 플레이어가 느낄 것 · 상세 규칙 · 공식 · 예외 상황 · 다른 시스템과의 관계 · 조절값 · 통과 기준. 몇 회에 나눠 쓸지는 어림이다 — 실제 진도에 맞춰 고친다.

3. ~~글을 따로 모아 둘지~~ — **정함 (2026-10-01)**: 글은 스트링 테이블에 모은다. 게임에 나오는 글(스트링)을 코드에 직접 적지 않고 파일에 따로 모아 두고, 글마다 이름(스트링 키)을 붙여 불러 쓴다. 데모는 한국어만 내지만 이 방식으로 만든다 — 나중에 번역을 붙일 때 드는 비용이 훨씬 작아진다. 스트링 키를 붙이는 규칙과 파일 양식은 케이스 데이터 GDD(M02)에서 정한다. (옛 표기 = "문장 이름표 구조")

   **미리 지킬 것** (2026-10-01 — The Balatro Timeline을 읽고 정리했다. 나중에 번역을 붙일 때 다시 만들지 않기 위한 것이다):
   1. 글을 코드나 씬에 직접 적지 않는다 — 전부 스트링 테이블에 둔다. (코드 작업, M03부터)
   2. 글씨를 텍스처에 섞어 그려 넣지 않는다 — 글자가 꼭 그림이나 모델이어야 하는 것은 글자 부분만 따로 떼어 언어별로 만들고, 목록으로 관리한다. (아트 작업 — 목록은 아래 7번)
   3. 문장을 조각내 이어 붙이지 않고, 통문장에 빈칸을 둔다 — 예: `{이름} 님은 {직무} 직무에 {결과} 처리되었습니다.` 빈칸의 자리는 언어마다 다르게 둘 수 있다. 한국어 조사(은/는, 이/가)도 빈칸 뒤에서 한 곳의 규칙으로 맞춘다. (케이스를 쓸 때, 코드 작업)
   4. 종이 틀과 자막 칸에 글 길이 여유를 둔다 — 영문은 약 30% 길어지고, 글꼴이 바뀌면 글자 폭과 줄 높이도 달라진다. (면접실 종이 소품, 화면 설계)
   5. 판정의 근거를 말장난에 걸지 않는다 — 웃음은 문장에 두고, 근거는 번역해도 남는 사실에 둔다. 말장난은 번역하지 않고 다시 쓴다. (케이스를 쓸 때)
   6. 글꼴은 언어마다 따로 고른다 — 그러려면 글꼴을 화면마다 직접 지정하지 않고, 역할 이름(본문 글꼴, 손글씨 글꼴 등)으로 걸어 한 곳에서 바꿔 끼울 수 있게 만든다. 유니티에서 하는 방법은 M03 코드 작업 때 공식 문서로 확인한다.
4. **정답 규칙** ("GDD 지침 ①"에서 정한다): 같은 지원자라도 그날 지침에 따라 정답이 달라지는 방식. systems-index의 고위험 항목이다 — 케이스를 적는 양식을 확정하기 전에 정한다.
5. **GDD 쓰는 순서** ("전체 흐름 살펴보기 ②"에서 확정한다): 지금 계획 = 하루 구조·결산 → 지침 → 판정(M01) → 책상 위 물건 다루기 → 케이스 데이터(M02). 흐름을 살펴본 결과에 따라 바뀔 수 있다. systems-index.md와 다른 마일스톤 파일에는 아직 옛 순서(케이스 데이터가 1번)가 적혀 있다 — 확정한 뒤에 한 번에 맞춘다.
6. **흐름에서 찾은 빈 곳** ([game-flow.md](../../design/gdd/game-flow.md) 6번): 승진하지 못한 Day 2에 무엇을 하는지, 데모 시간(목표 15~20분인데 적힌 건수로는 업무만 22분 이상), 섞어 뽑기와 데모 분량. "전체 흐름 살펴보기 ②"에서 방향을 정하고 "GDD 하루 구조 ②"에서 규칙으로 적는다.
7. ~~도장 자국을 글자로 할지 기호로 할지~~ — **정함 (2026-10-01)**: 글자로 하고, 언어별 그림으로 만든다. 언어에 따라 바꿔 끼우는 것은 스트링만이 아니다 — 글꼴·그림·3D 모델도 언어별로 만들어 이름으로 걸어 두고, 언어 설정에 따라 바꾼다(화면이나 코드에 한국어 것을 직접 걸지 않는다). 데모는 한국어만 내므로 지금 만드는 것은 한국어 것뿐이다. 유니티에서 하는 방법은 M03 코드 작업 때 공식 문서로 확인한다.
